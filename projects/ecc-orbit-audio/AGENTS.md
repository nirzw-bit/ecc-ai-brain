# ECC ORBIT Audio Project — Working Instructions

These instructions apply only to `projects/ecc-orbit-audio/`.

## Scope and evidence
- Treat this directory as a documentation and research archive, not an executable application.
- Keep source evidence, prior assistant reports, inference, and unknowns explicitly distinguished.
- Never claim that audio was transcribed, diarized, language-identified, legally reviewed, or externally researched unless there is recorded evidence of that work.
- Use neutral speaker labels (Speaker A / Speaker B). Do not infer participant identities.

## Privacy and consent gates
- The archive records that one participant was unaware of the recording. Keep this fact visible in future handoffs.
- Do not add the original recording, derived voice clips, or identifiable transcript excerpts to Git.
- Do not upload audio or transcripts to external services without a separately documented, informed authorization covering that processing.
- Private analysis, AI processing, quotation, voice use, and public release are distinct permission decisions.
- Keep public release on hold until the privacy/consent and legal review gates are resolved.
- Never store credentials, tokens, private contact details, or unnecessary sensitive personal information here.

## Change discipline
- Preserve the original source and existing project history; make additive, reviewable changes.
- Do not introduce an application runtime, dependencies, deployment configuration, scheduled jobs, or infrastructure into this archive without a separate technical plan and explicit approval.
- Use a separate branch and pull request for changes. Describe what changed and what was not tested.
- Do not treat a passing documentation check as validation of audio contents, consent, legal compliance, or application behavior.

## Development environment
This directory currently contains project documentation only. A Codespaces devcontainer, runtime, and application test suite are intentionally not defined. Add them only when an actual application/tool implementation is introduced and its runtime requirements are known.
